# 제작 로드맵 (2026-11 합의안)

> 순서는 의존 관계와 "문명처럼 한 턴만 더가 되는가"를 기준으로 정했다. 각 단계는 `CLAUDE.md`의 **출시 전 소비자 검사**를 통과해야 끝난다. 통과하지 못하면 다음 단계로 넘어가지 않고 불합격을 그대로 보고한다.
> 시간 추정은 하지 않는다. 크기는 상대적으로만 적는다.

## 항상 적용되는 것
- **원칙 0**: 수량이 아니라 퀄리티. 가짜 선택지, 빈껍데기 변수, 돌려막기 금지.
- **원칙 0-2 / 0-3**: 플레이하는 느낌(문명식 턴 리듬, 직접 조작), UI도 게임성의 일부.
- **제1원칙**: 모든 디테일은 구체적이고 말이 되어야 한다. 상수는 근거 또는 "임시" 표기.
- **감사 자동화**: 상수나 규칙을 바꿀 때마다 변수 감사(`npm run audit`)를 다시 돌린다.
- **지루함 지표**: 정체된 턴의 비율, 한 턴에 끝나는 타이머 수, 아무 결정 없이 지난 턴의 비율. 기준 아래면 불합격.
- **사람이 해 보는 지점**: 단계 2, 4, 6 직후에 사용자에게 직접 플레이를 요청한다. 재미는 스크립트로 판정하지 않는다.

## 일부러 미루거나 뺀 것
멀티플레이, 실제 역사 고증(독자 세계관), 3개 이상의 플레이 가능 세력, 외부 LLM API(선택 기능으로만 검토: 핵심 의사결정에는 쓰지 않는다).

## 알려진 큰 위험
1. **포위 표현**: 지금의 전선(x가 y의 함수)은 포위·보급 단절을 표현하지 못한다. 3단계에서 지형과 함께 표현 방식을 바꿀지 결정한다.
2. **판이 길다**: 현재 이기는 길이 30턴 이상이다. 2단계의 성장 층이 이 긴 판을 지루하지 않게 만드는지가 핵심이다.
3. **재미는 스크립트로 판정할 수 없다**: 사람이 해 보는 지점을 건너뛰지 않는다.
