- 개간 레버는 시기를 고르는 투자 결정이지만 폭이 작다("늦게 하는 쪽이 거의 항상 낫다", `MODEL.md` 7절). 개간 노동량은 근거 없는 임시값이다.

## 단계 2a (법령·제도 + 계절 보정) — 총평: 법령 선택은 가짜가 아니지만 "매 턴 끝나는 것" 기준은 여전히 미달

### 불합격 / 미흡 (먼저)
| 항목 | 증거 | 내용 |
|---|---|---|
| **통과 기준 미달: 매 턴 끝나는 것** | `timers-measure` (12턴 측정) | 아무것도 안 하면 12턴 중 5턴, 법령 연구를 계속해도 6턴에만 이번 턴에 일어나는 일이 있다(파종·수확·훈련 마침). **여름과 겨울 턴은 여전히 비어 있다.** 법령 연구는 180일이라 완료 시점이 턴 경계에 걸려 "이번 턴에 끝나는 일"로 잘 안 잡히고, 슬롯 2개가 차면 연구할 것이 없어진다. 건설 큐(2b)와 지휘관(2c)이 필요하다 |
| **둔전제가 약하다** | 법령 균형표 | 방어·영리에서 영토가 크게 낮고(21%/25% vs 법령 없음 24%/35%) 이점은 기아 방지뿐이다. 총동원에서만 뚜렷하다. 모든 상황에서 밀리지는 않지만 "안전한 약한 선택"이 되어 있다 |
| **병참 개혁의 대가가 크다** | 같은 표 | 총동원에서 영토 52%지만 기아 사망 1,796명. 이기려면 많은 사람이 굶는다. 플레이어가 이 대가를 알고 고르도록 카드에 실제 숫자를 보여 주지만, 이것이 "좋은 불편"인지 "불쾌"인지는 사람이 판정해야 한다 |
| **근거 없는 임시값** | 구성 | 법령 수치와 계절 배율 전부 임시. 법령 선택의 균형이 이 값들에 극도로 민감할 수 있다 |
| **고정된 적의 법령 순서** | `edicts.ts` | 적은 성향별로 정해진 순서로 법령을 연구한다(정복형: 병참 → 상비군). 플레이어가 예측할 수 있고, 적은 우리 법령에 반응하지 않는다 |
| **카드가 길다** | 스크린샷 | 법령 카드 3장 + 숫자로 오른쪽 열이 길다. 복잡도 한도 관점에서 확인 필요(턴당 결정 수는 적지만 읽을 양이 많다) |
| **사람 판정 필요** | — | 법령 선택이 "내가 나라를 만들어 간다"는 느낌을 주는가는 사람이 해 봐야 안다 |

### 검사에서 찾아 고친 것
- **병참 개혁이 너무 강했다**: 고정 규칙 AI 상대 측정에서 단순 공세가 6시드 중 5번 승리 → 효과를 줄이고 대가를 키움.
- **탐색형 AI(실제 게임)로 다시 재니 상비군제가 함정**이었다(법령 없음보다 약함). 징집 상한 감소만 대가로 두었던 것이 이점을 압도 → 전투력 +20%를 주는 대신 식량 +50%와 해산 복귀 50%를 대가로 붙임. 고정 규칙 AI에서만 재 봤다면 놓쳤을 문제다.
- **법령 폐지가 한 번 클릭으로 실행**되어(되살리려면 180일) 억울한 실수가 가능했다 → 두 번 눌러야 폐지, 4초 뒤 풀림.
- 고정 규칙 AI의 균형 회귀 시험이 적의 법령 때문에 깨져 "적 법령 끄기" 옵션을 두고 회귀 시험 전용으로 사용.

| 항목 | 증거 | 내용 |

| **사람 판정 필요** | — | "이 적이 살아 있는 상대처럼 느껴지는가"는 사람이 해 봐야 안다 |

### 검사에서 찾아 고친 것
- 예측 갱신: 탐색형 적을 포함한 예측은 0.3~0.5초가 걸려 끄는 동안 화면이 버벅일 수 있었다 → 끄는 동안은 낡은 예상을 흐리게 보여 주고 멈춘 뒤 약 0.27초 만에 한 번만 다시 계산한다. (측정)
- 예상 문구에서 "다시 계산하는 중" 표시가 코드에 반영되지 않은 것을 화면 확인 중에 발견해 고쳤다.

## 단계 0 (변수 감사) — 총평: 빈껍데기 1건 제거, 구조적 문제 여러 건 확인, 감사 도구 결함 2건 발견·수정. 절반만 끝남

자세한 내용은 `AUDIT.md`. 불합격·미흡만 요약한다.

- **감사 도구의 결함으로 처음 결과 일부가 틀렸다**: (1) 시작 데이터 패치가 전쟁에 안 쓰이는 `START_REGIONS`를 먼저 바꿔 곡창·경작지·지배층 제거가 "변화 없음"으로 잘못 나옴. (2) 평균만 비교해서 분산만 바꾸는 변수(전황 변수, 기상)를 "빈껍데기"로 오판할 뻔함. 둘 다 고쳐 다시 돌렸다. 같은 종류의 오판이 앞으로도 가능하다(정책이 쓰지 않는 기능, 문턱 설정).
- **개간 레버는 전쟁 게임에서 빈껍데기**였다 (방어+개간 vs 방어: 영토 +0.4%p, 인구 +35명, 수확 −200t). UI와 타이머에서 제거했다. 이 레버는 M1.5에서 "시기를 고르는 투자 결정"이라고 평가했지만 전쟁이 들어오자 의미를 잃었다. 이전 평가가 틀린 것은 아니고 전제가 바뀐 것이다.
- **장인·상인·지배층은 여전히 고유 역할이 없다**(단계 4로 미룸).
- **난이도가 한 숫자에 달린 절벽**: 적의 병력 따라가기 배율(0.5 ↔ 1.5)이 승패를 뒤집는다. 근본 해결은 단계 1.
- **곡식 수지가 비대칭 문턱 근처**: 근거 없는 임시 상수 몇 개가 기근 여부를 가른다. 상수 근거 조사가 더 필요하다.
- 합격: 읽는 곳 지도에서 죽은 상수 0개, 화면 전용 상수 0개, 감사 자동화(`npm run audit`).

## 폐기한 설계: 계층별 분배 · 공공 비축 · 구휼 (M2 후보였음)

계획했던 M2("계층별 소유, 세금·지대, 구휼")를 코드로 옮겨 측정했고, **같은 검사 기준으로 불합격시켜 폐기했다.** 코드는 저장소에 두지 않았다.

**구현했던 것**: 수확을 세금(공공곡창, 비축 목표 일수까지) / 지대 32%(지배층) / 농가 몫으로 분배. 지배층이 먼저 먹고 장인·상인은 지배층의 곡식을 현물 급료로 받음. 공공곡창을 열면 굶는 사람에게 부족분을 풀어 줌.

**측정 결과** (평형 상태 60년차에 흉년, 이후 5년 관찰, 기아 사망은 농민/장인·상인/지배층):

| 정책 | 흉년 1회(0.55) | 2년 연속 흉년(0.5) |
|---|---|---|
| 비축 0일, 구휼 닫음 | 인구 99.4%, 0 / 807 / 271 | 95.7%, 19 / 1,585 / 532 |
| 비축 60일, 구휼 열림 | 102.4%, 0 / 133 / 45 | 97.1%, 619 / 835 / 283 |
| 비축 180일, 구휼 열림 | 103%, 0 / 0 / 0 | 98.8%, 827 / 288 / 98 |
| 비축 180일, 구휼 닫음 | 99.3%, 0 / 805 / 271 | 90.8%, 1,480 / 1,560 / 527 |

**불합격 사유**
1. **비용 없는 보험**: 비축을 늘리고 구휼을 여는 것이 모든 시나리오에서 이득이고 평년에는 비용이 눈에 띄지 않았다. 세금은 농가 곡식을 공공곡창으로 옮길 뿐이라 총량이 같다. "최대로 쌓고 항상 연다"가 정답이라 레버가 아니다.
2. **쓸모없는 계층**: 장인·상인이 아무것도 생산하지 않아서, 가장 많이 죽는 것이 이들인데도 통치자에게 손해가 없다. 누구를 먹일지가 선택이 되려면 계층마다 통치자에게 다른 가치(생산, 병력, 세수)가 있어야 한다.
3. **설정 불일치**: 시작 구성(농민 60/장인 30/지배 10)과 지대 32%가 맞지 않아 평년에도 장인이 만성적으로 굶었다(150년 평균 누적 기아 사망 농민 약 11,000, 장인·상인 약 6,200, 지배층 약 2,100). 지배층이 굶은 것은 장인 급료를 먼저 내줘서 자기 몫까지 바닥난 모델링 결함이었다.

**교훈**: 분배 구조만으로는 선택이 생기지 않는다. 비축과 곡식에 **경쟁하는 사용처**(군대 보급, 징집으로 빠지는 노동력, 정복 비용)가 있어야 비축에 기회비용이 생기고, 계층에 **서로 다른 가치**가 있어야 누구를 살릴지가 결정이 된다. 그 경쟁 상대가 지금 모델에 없다.


## 단계 2b 건설 큐 — 적대적 검사 (2026-11)
**불합격·미흡 (먼저)**
1. **요새·도로의 효과가 작고 정책에 따라 갈린다 — 확정적 이득이 증명되지 않았다.** `docs/audit/build-compare-scripted.md`(시드 8, 24턴, 고정 규칙 적): 요새는 방치(영토 8→15%)·방어개간(26→28%)에서 이득, 단순공세(37→32%)·영리(35→32%)에서 손해. 도로는 총동원에서만 승리 2회, 대신 기아 사망 +45%. 표본이 8이라 ±3%p는 잡음일 수 있다. 상수를 세 번 바꿔 봤고(0.35/150 → 0.7/300 → 0.5/220), 0.35에서는 거의 효과 없음, 0.7에서는 방어 정책이 오히려 졌다(전선이 넘은 요새가 적의 것이 되는 함정). 값은 임시이며 "쓸모 있는 레버"라는 증거는 아직 없다. **탐색형 AI(AI_MODE=search)로는 측정하지 않았다.**
2. 감사 정책의 건설 규칙이 단순하다(가장 밀리는 구간에 요새, 여름에 중앙 도로). 사람은 더 잘 쓸 수 있고, 이 표는 그 상한·하한이 아니다.
3. 요새는 완공까지 90일이라 이번 턴 예상(미리 보기)에는 이득이 보이지 않는다. 다음 계절에야 보상이 보인다 — 즉각 피드백 원칙에는 약하다. 대신 공사 중인 것은 지도 진행 막대와 "이번 계절에 일어날 일"로 보인다.
4. 지휘관(2c) 미착수. 매 턴 끝나는 것 기준은 다시 재지 않았다(요새·도로 완공이 일부 턴을 채울 뿐).
5. 폰에서는 점 누르기가 여전히 어렵다(점 간격 약 14px).

**합격 (증거)**
- 시험 129개 통과(건설 17개: 수명·취소·제약·효과·결정성·봄/여름 일손 손실·적 AI).
- 화면 확인: 데스크톱/폰 × 라이트/다크 스크린샷으로 구간 패널의 건설 항목, 지도의 도로(점선→실선)·요새(점선 네모+진행 막대), 타이머 항목, 참모 권유("지금이 건설하기 좋은 때")를 직접 봤다.
- 되돌릴 방법: 진행이 있는 공사의 취소는 한 번 더 눌러야 하고(날수 표시), 진행 0이면 바로 취소된다.
- 비용 고지: 봄·가을에 인부를 빼면 수확·파종 일손이 준다는 경고를 구간 패널에 띄운다.

### 2b 측정 보강 (고정 규칙 적 시드 24, 탐색형 적 시드 8)
- 탐색형 적(`docs/audit/build-compare-search.md`): 요새·도로의 단독 효과는 영토 ±3%p 이내로 시드 8개로는 잡음과 구분되지 않는다. 눈에 띄는 것은 총동원에서 요새+도로(35→49%, 승 2회)뿐이며, 그때 기아 사망이 599→1,283명으로 두 배가 된다.
- 도로의 기아 증가는 여름에 시작한 180일 공사가 가을 수확일을 가로지르기 때문이다(감사 정책의 선택 결과). 이 비용이 플레이어에게 보이도록, 건설 버튼에 "N일 뒤 수확일에 일손이 빠집니다" 경고를 추가했다.
- 판정(구조 검사): 빈껍데기 아님, 한쪽 우세 아님(요새는 소극 정책에서 이득·공세 정책에서 손해). 도로는 효과가 작아 **미증명**이므로 단계 7.5 균형 조정에서 유지/삭제를 결정한다.
