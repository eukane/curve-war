# 변수 감사 (로드맵 단계 0)

목적: 빈껍데기 변수, 가짜 레버, 다른 변수에 좌우되어 의미가 사라지는 변수를 찾는다. 작업물 안에서 "있어 보이는" 것으로 판단하지 않고 **실제로 바꿔서 돌려 본** 결과로 판단한다.

도구: `npm run audit:static`(읽는 곳 지도), `npm run audit`(상수 변형 116개 × 정책 6개 × 시드 6개 × 24턴 + 짝 검사, 약 5분). 원자료: `docs/audit/sensitivity-report.md`, `docs/audit/static-report.md`.

## 범위와 한계 (먼저)
- 정책 6개(방치, 방어, 영리, 총동원, 단순 공세, 방어+개간)와 시드 6개, 24턴(6년) 안에서만 본다. **정책이 쓰지 않는 기능은 "효과 없음"이 아니라 "판단 보류"다.** 사람은 더 다양하게 쓴다.
- "눈에 띄는 변화"의 문턱은 임의로 정했다(영토 3%p, 기아 사망 400명, 승패 0.34, 인구 1,500명, 소요 턴 2). 문턱 아래의 효과는 못 본다.
- 평균 차이만 보면 흔들림(분산)만 바꾸는 변수를 놓친다. 이번에 분산 검사를 추가했다.
- 시드 6개라 통계가 거칠다. 같은 설정에서 시드 집합만 바꿔도 총동원의 영토와 인구가 문턱을 넘어 달라졌다. 이 지표들의 작은 차이는 잡음일 수 있다.

## 감사 도구 자체의 결함 (발견하고 고침)
1. **패치 대상 오류**: 시작 데이터 변형이 전쟁에 쓰이지 않는 `START_REGIONS`를 먼저 바꿔서, 곡창·경작지·지배층 제거가 "변화 없음"으로 잘못 나왔다. `sideRegion` 안쪽만 바꾸도록 고쳐 다시 돌렸다. (고친 뒤: 경작지 ×0.7과 곡창 ×0.5/×2는 기아 사망을 1,000~1,400명 바꾸고, 지배층 제거는 총동원 기아를 −1,300명 바꾼다.)
2. **평균만 비교**: 전황 변수(LUCK)와 기상 변동이 "변화 없음"으로 나왔다. 평균은 안 바꾸고 흔들림만 키우는 변수라서 구조적으로 못 잡은 것이다. 분산 검사를 추가해 보니 **전황 변수를 없애면 시드별 결과의 흔들림이 0.39배, 기상 변동을 없애면 0.31배**로 줄었다(잡음 수준 0.78배). 둘 다 빈껍데기가 아니고, 판이 매번 달라지는 이유다.

## 불합격 / 문제 (먼저)

### A. 빈껍데기로 확인되어 조치한 것
| 대상 | 증거 | 조치 |
|---|---|---|
| **개간 레버** (개간 노동, 새 땅 지력, 개간 사업 UI) | 방어 vs 방어+개간: 영토 49% → 50%, 인구 +35명, 수확 **−200t**(일손을 빼서), 기아 사망 +37명. 상수 ×0.5/×2도 어떤 지표도 바꾸지 못함 | **UI와 타이머에서 제거.** 시뮬레이션 코드와 시험은 남김("대기 중 기능"). 전쟁 중에는 인구가 수용력(38,500명)보다 한참 아래(약 29,000명)라 새 땅이 쓰일 일이 없다. 인구가 수용력에 닿는 상황이 생기면(세계 설정, 정복 규모, 정착) 되살린다 |
| `SPRING_CHECK_DAY_OF_YEAR`, `HARVEST_ALERT_DAY_OF_YEAR` | 읽는 곳 지도: 폐기한 이벤트 고정물에서만 읽힘 | 상수 파일에서 고정물 파일로 이동 |

### B. 고유한 역할이 없는 것 (판단 필요)
| 대상 | 증거 | 판단 |
|---|---|---|
| **장인·상인** | 8,000→0: 인구가 줄 뿐. 농민으로 바꾸면 총동원의 기아 −1,740명(일손 증가). 읽는 곳: 시작 데이터와 타입 정의뿐 | "일 안 하는 입"일 뿐 계층으로서의 역할이 없다. **로드맵 단계 4(사회 구조)에서 역할을 주거나 그때까지 "비농업 인구" 하나로 합친다.** 지금은 그대로 두고 문서에 "빈껍데기 후보"로 표시 |
| **지배층** | 3,000→0: 총동원 기아 −1,300명, 단순공세 인구 −3,014명(사람이 줄어서). 고유한 규칙 없음 | 위와 같음 |
| **마을 점** | 마을 수 보고를 제거해도 모든 지표가 같음(보고에만 영향) | 독립 변수가 아니라 **면적의 표시 단위**다(마을은 균등 배치이고 인구는 면적 비례로 넘어간다). 보고에 "마을 N곳"이라고 쓰는 것은 괜찮지만 별개의 보상처럼 보이면 안 된다. 유지하고 문서에 "표시 단위"라고 명시 |
| **굶는 군대 약화** | 제거해도 총동원 기아 +525명뿐 | 효과가 약하다. 규칙 자체는 말이 되므로 유지하되, 군량 부족이 실제로 문제가 되는 상황(포위, 약탈)에서 의미가 커질 것으로 기대. 추적 대상 |

### C. 효과가 문턱 아래인 상수 (정책 범위 안에서)
| 상수 | 관찰 | 판단 |
|---|---|---|
| `STORAGE_LOSS_PER_YEAR` | ×0.5, ×2 모두 변화 없음 | 곡창 손실은 곡식 수지의 1% 안팎이라 전쟁 결과에 안 닿는다. 약탈·방화(곡창 공격)나 역병 단계에서 의미가 생길 수 있어 유지, "미미"로 표시 |
| `SOWING_DAY_OF_YEAR`, `HARVEST_DAY_OF_YEAR` ±30일 | 수확 210일만 총동원 기아 +512 | 달력 사실이다. 턴 단위에서는 파종·수확이 같은 계절 안에 있기만 하면 된다 |
| `BIRTH_SUPPRESSION_PER_DEFICIT` | 변화 없음 | 기근 때 출생 감소 기울기. 기아가 드문 정책에서는 안 읽힌다. 대기근 단계(6)에서 재검사 |
| `WEATHER_MIN/MAX` | 평균·분산 모두 거의 없음 | 극단 값의 경계라 발생이 드물다. 안전장치로 유지 |
| `FOCUS_REF_UNITS`, `FOCUS_MAX_BONUS ×2` | 변화 없음 (×0.5와 제거는 영향이 있음) | 집중 가중치 자체는 역할이 있고(제거 시 방어 인구 −2,336) 상한 근처는 안 쓰인다 |
| `SUPPLY_MIN ×0.5` | 변화 없음 (×2는 영향) | 보급 배율의 하한까지 내려가는 상황이 정책에서 안 나온다 |
| `AI_MAX_LEVY_SHARE_PER_TURN` | 단독으로는 ×0.5, ×2 모두 변화 없음 | **짝 검사에서 훈련 기간과 상호작용**(아래). 단독 검사만으로는 빈껍데기처럼 보인다 |
| AI 공격성 1.0 | 0.6과 같음 | 공격성이 0.6 근처에서 포화된다(0.3은 영향 있음). 상한이 의미 없음 |
| `V_RETREAT_UNITS`, 자발적 후퇴 제거 | 변화 없음 | **정책이 후퇴를 쓰지 않았다.** 판단 보류. 사람이 쓰는 기능이므로 후퇴를 쓰는 정책을 추가해 다시 본다 |

### D. 지배 변수와 절벽 (난이도가 한 값에 달려 있음)
| 대상 | 관찰 |
|---|---|
| **적의 병력 따라가기 배율** (현재 1.05) | 0.5로 낮추면 단순 공세가 19턴 일찍 승리하고, 1.5로 올리면 영리한 정책의 인구가 −15,182명. **한 숫자가 게임 난이도를 사실상 결정하는 절벽**이다 |
| 적의 방어 집중 | 없애면 단순 공세가 13턴 일찍 승리, 방치는 11턴 더 버틴다. 단순 스팸 승리를 막는 핵심 규칙이다 |
| **적의 수확 약점**(수확 턴 따라가기 1.05로 제거) | 영리 정책 인구 −8,508명. 이 약점이 플레이어에게 유리한 규칙 하나를 실제로 떠받치고 있다 |
| 보급 배율 | 제거하면 방어 인구 −15,757명, 영토 −28%p. 방어자의 이점의 핵심 |
| 곡식 수지 (`YIELD`, `GRAIN_KG_PER_PERSON_DAY`, `HA_PER_FARMER`, `SEED`) | ×0.5 쪽은 기아 사망 +8,000~9,000명, ×2 쪽은 거의 변화 없음: **비대칭 문턱**이다. 현재 값이 문턱 가까이에 있다는 뜻이고, 어느 쪽으로든 조금만 틀리면 기근이 터진다 |
| `MAX_LEVY_SHARE_OF_FARMERS` | ×2면 총동원 인구 −12,409명(파국), ×0.5면 +10,406명 |

### E. 짝(2×2) 검사: 한 변수의 역할이 다른 변수에 좌우되는 경우
| 짝 | 결과 |
|---|---|
| `LEVY_TRAINING_DAYS` × `AI_MAX_LEVY_SHARE_PER_TURN` | 총동원의 기아에서 **상호작용(598)이 두 주효과(412, 342)보다 크다.** AI 징집 상한은 단독으로 의미가 없어 보였지만 훈련 기간이 길 때만 의미가 있다 |
| `CASUALTY_RATE_PER_DAY` × `V_MAX_KM_PER_DAY` | 방치 정책의 인구와 영토에서 상호작용이 주효과보다 크다. 사상률과 전진 속도는 함께 정해야 한다 |
| `GRAIN_KG_PER_PERSON_DAY` × `YIELD_KG_PER_HA` | 상호작용이 주효과와 거의 같다. 두 상수는 사실상 **하나의 값(수지 비율)**이다. 둘을 따로 조정하는 것은 의미가 없다 |
| `SUPPLY_FALLOFF` × `FOCUS_MAX_BONUS`, `HA_PER_FARMER` × `MAX_LEVY`, `PRESSURE_SCALE` × `LUCK` | 문턱을 넘는 상호작용 없음(독립적) |

## 합격 (증거)
- 읽는 곳 지도에서 아무도 안 읽는 상수는 없다(위 이동 후). 화면 전용 상수도 없다.
- 규칙이 실제로 결과를 바꾼다는 증거: 적 방어 집중(스팸 승리를 막음), 보급 배율, 훈련 기간(제거 시 단순공세 인구 −3,426명), 집중 가중치, 병력 징집 상한, 사상률, 곡식 수지.
- 전황 변수와 기상 변동은 판의 변동성의 원천이다(분산 검사).

## 이 감사로 바뀐 것
1. 개간 UI와 타이머 제거 (시뮬레이션 코드는 대기 중 기능으로 보존).
2. 죽은 상수 2개를 폐기 이벤트 고정물로 이동.
3. 감사 도구 자동화 (`npm run audit`, `audit:static`). 상수나 규칙을 바꾼 뒤에는 다시 돌린다.

## 남은 일 (이 단계가 끝나지 않은 부분)
- 장인·상인·지배층 처리는 단계 4로 미뤘다. 그때까지 "빈껍데기 후보"로 남는다.
- **후퇴를 쓰는 정책, 정찰 같은 것을 쓰는 정책을 추가**해 판단 보류 항목을 다시 검사해야 한다.
- 적의 병력 따라가기 배율이라는 절벽은 단계 1(적 AI 탐색형 교체)에서 근본적으로 다룬다. 지금의 고정 규칙은 임시 장치다.
- 곡식 수지의 비대칭 문턱은 "현재 값이 근거 없는 임시값(수확량 근사, 소비 근사)"이라는 점과 직결된다. 근거 조사를 더 해야 하고, 값이 바뀌면 이 감사를 다시 돌려야 한다.
